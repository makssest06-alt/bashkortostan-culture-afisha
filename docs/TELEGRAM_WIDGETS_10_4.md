## 1. Зачем использовать Bot API 10.4 Widgets в проекте

Обновление Telegram Bot API 10.4 (выпущено 9 ноября 2026 года) позволяет боту отправлять компактные самодостаточные HTML+CSS+SVG+JS блоки, которые рендерятся клиентом Telegram **непосредственно внутри пузыря сообщения** без запуска внешнего WebView.

Для «Афиши культуры Башкортостана» на хакатоне «Кибер 102» это решает сразу две задачи:

1. **Продуктовая скорость и визуальный код региона (`0 мс` холодного старта):** пользователь видит башкирскую палитру (`design/culture-kit/`), интерактивные лепестки курая, чипы `hard/soft` условий, сравнение 2–3 сеансов и живой таймлайн плана дня прямо в потоке диалога без спама десятками inline-кнопок.
2. **Эталонная изоляция по требованиям ИБ:** код виджета исполняется не в браузере, а во встроенном движке **QuickJS** с полным физическим отключением любых сетевых интерфейсов (`NetworkDisabledError`).

## 2. Двухуровневая архитектура в Telegram

Из-за строгих ограничений размера и высоты пузыря интерфейс в Telegram делится на два дополняющих друг друга уровня:

| Уровень | Технология | Что решает |
|---|---|---|
| **Уровень 1: внутри пузыря чата** | Bot API 10.4 HTML Widget (`sendWidget` + `editMessageWidgetData` + `answerWidgetQuery`) | Пульт `hard/soft` чипов и 7 лепестков курая, быстрое сравнение до 3 `Occurrence`, компактный таймлайн дня (2–3 слота) и мгновенное превью замены при отмене сеанса (`plan_attention`) |
| **Уровень 2: полный экран по запросу** | Кнопка `reply_markup` (`web_app` / HTTPS) под тем же сообщением или `TelegramWidget.openTelegramLink(...)` | Интерактивная карта площадок (MapLibre), полные тексты описаний и расписаний (`> 1024` байт), экспорт открытки маршрута |
| **Групповой бонус из Bot API 10.4** | `ephemeral_message_parameters` с `callback_query_id` без `receiver_user_id` | Персональные эфемерные ответы участникам группового чата в production (например, проверка общего маршрута под личный бюджет без засорения группы) |

## 3. Свойства безопасности и соответствие `SECURITY_THREAT_MODEL.md`

Архитектура HTML-виджетов Bot API 10.4 усиливает существующие инварианты проекта (`INV-RO`, `INV-BACKEND-AUTHZ`, `INV-UNTRUSTED`, `INV-RENDER`):

1. **Полный запрет сети в песочнице:** вызовы `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`, а также загрузка внешних скриптов, шрифтов, стилей и `<img src="https://...">` заблокированы на уровне клиента (`NetworkDisabledError`). Даже если в заголовке внешней афиши встретится вредоносная строка, эксфильтрация данных на внешний домен невозможна.
2. **Неизменяемый код + серверное состояние:** поле `html` фиксируется в момент вызова `sendWidget` и никогда не модифицируется. Меняются только строковые поля `chat_data` и `public_data`, право записи в которые есть исключительно у бота (`editMessageWidgetData`).
3. **Единый 64-байтный формат запросов с `TELEGRAM_RESEARCH.md`:** единственный способ виджета обратиться к боту — `TelegramWidget.request(data)` размером **1–64 байта UTF-8**, приходящий на backend как `Update.widget_query` с аутентифицированным полем `WidgetQuery.from`. Мы используем тот же формат непрозрачных серверных токенов `v1:<opaque_token>`, что и для `CallbackQuery`.
4. **Строгий рендеринг недоверенных строк:** внутри JS-кода виджета названия событий, площадок и цен из `chat_data` вставляются в DOM **только через `element.textContent`**, никогда через `innerHTML`.

## 4. Транспортный цикл `WidgetQuery` и двойное подтверждение

По аналогии с разделом 2 и 12 `docs/TELEGRAM_RESEARCH.md`, обработка `Update.widget_query` обязана соблюдать порядок:

```text
Webhook POST
→ проверка заголовка X-Telegram-Bot-Api-Secret-Token (constant-time)
→ синтаксическая валидация + durable запись update_id / widget_query.id (dedupe)
→ HTTP 200
→ worker: проверка владельца сессии (WidgetQuery.from.id), срока жизни токена v1:<token>, ревизии и allowlist
→ атомарное чтение или подтверждённая мутация сессии/плана
→ answerWidgetQuery(widget_query_id, data = новый компактный JSON ≤ 1024 B)   [мгновенный ответ в Promise виджета]
→ canonical diff и editMessageWidgetData(chat_id, message_id, chat_data = JSON ≤ 1024 B) [персистентность пузыря]
```

Ключевые детали протокола:
- `answerWidgetQuery` возвращает `data` (до 1024 байт) только в экземпляр виджета, отправивший запрос (`{ result }`), но **не меняет** сохранённое состояние сообщения. Чтобы при прокрутке чата или перезапуске клиента состояние сохранилось, адаптер синхронно обновляет `chat_data` через `editMessageWidgetData`.
- В JSON состояния (`contracts/telegram_widget_state.schema.json`) хранится монотонная ревизия `r`. Скрипт виджета хранит максимальный увиденный `r` и игнорирует запоздавшие события `chatDataChanged` / ответы с меньшим `r`.
- В личном чате с ботом (`private chat`) спецификация разрешает 1 фоновый вызов `TelegramWidget.request("v1:sync:...")` без тапа при появлении пузыря на экране (и не чаще раза в 5 секунд, пока он виден). Это позволяет безопасно подсвечивать `attention`-статус при открытии старого плана.

## 5. Жёсткие технические лимиты Bot API 10.4 (обязательный чек-лист)

Все значения ниже взяты напрямую из официальной спецификации `core.telegram.org/bots/widgets` и `core.telegram.org/bots/api#sendwidget`:

### 5.1. Бюджеты байтов

| Поле / метод | Жёсткий лимит Telegram | Правило реализации в нашем адаптере |
|---|---|---|
| `sendWidget.html` (сырой UTF-8) | `1 .. 32 768` байт | Один статический минифицированный шаблон без зашитых текстов событий |
| `sendWidget.html` после `zlib` (level 9) | **`<= 4 096` байт** | Автотест в CI проверяет `len(zlib.compress(html.encode("utf-8"), 9)) <= 4096` (целевой бюджет шаблона: `2.5–3.3 КБ`) |
| `chat_data` / `public_data` | **`0 .. 1 024` байт UTF-8** | Кириллица в UTF-8 занимает 2 байта на символ (~350–400 русских букв со структурой JSON). Используем только компактную кортежную схему `contracts/telegram_widget_state.schema.json` и локальный усекатель строк по байтам UTF-8 до вызова API |
| `TelegramWidget.request(data)` | **`1 .. 64` байт UTF-8** | Только `"v1:" + opaque_short_token`; параллельные запросы дают ошибку `BUSY` (блокируем повторный клик в UI до ответа) |
| `answerWidgetQuery.data` | **`0 .. 1 024` байт UTF-8** | Тот же сериализованный JSON состояния или короткий код ошибки |
| `sendWidget.caption` | `0 .. 1 024` символов | Всегда заполняется читаемой текстовой сводкой для fallback-клиентов |

### 5.2. Ограничения песочницы QuickJS (Profile 1) и вёрстки

1. **Запрет форм и клавиатуры:** теги `<form>`, `<input>`, `<textarea>`, `<select>`, `<option>`, `<label>`, `<dialog>` не поддерживаются; виджет не получает фокус клавиатуры. Любой текстовый или голосовой ввод пользователь отправляет обычным сообщением боту.
2. **Высота `50–600 px` и отсутствие скролла:** `overflow: auto` и `overflow: scroll` не поддерживаются; всё содержимое выше высоты пузыря (максимум `600 px`) жёстко обрезается. Единицы `vh`, `dvh`, `svh` запрещены. Целевая высота наших виджетов на ширине `320 px` — до `500 px` (не более 3 слотов в одном пузыре).
3. **Поддерживаемая и запрещённая графика:**
   - **Разрешено:** inline `<svg>` (`svg`, `g`, `path`, `rect`, `circle`, `polygon`, `linearGradient`, `radialGradient`), CSS `flex`/`grid`, переменные темы `--tg-theme-*`, функция `light-dark()` и `@media (prefers-color-scheme: dark)` (следуют теме чата!), `HapticFeedback`.
   - **Запрещено (приведёт к отбрасыванию стилей или остановке `"Widget stopped"`):** SVG `<clipPath>`, `<mask>`, `<pattern>`, `fe*`-фильтры, SMIL `<animate>`, `<foreignObject>`, именованные шрифты в `font-family`, `-webkit-line-clamp`, 3D-трансформации.
   - **Лимит композитинга:** одновременно на экране может быть **не более 16 элементов** с `opacity < 1`, размытым `box-shadow`, `filter` или `backdrop-filter`. Приглушённые чипы и разделители кускара верстаются через `rgba(...)`, `fill-opacity` или `var(--tg-theme-hint-color)`, **не через `opacity`**.
4. **Безопасные зоны касаний и времени сообщения:**
   - Левые `20 px` пузыря зарезервированы под системный жест «Назад» смартфона — интерактивные кнопки и лепестки курая размещаются с отступом `>= 20 px` от левого края.
   - Таповые вызовы (`request`, `openLink`, `openTelegramLink`, `copyText`) вызываются строго синхронно внутри обработчика `click` / `pointerup` (не после `await` или таймера и не в `pointerdown`).
   - Для горизонтального свайпа вкладок карточек используется `touch-action: pan-y` с корректной отменой подсветки по `pointercancel`.

## 6. Доступность в Production vs Test Server и стратегия Fallback

Согласно разделу *Availability* официальной документации Bot API 10.4 на момент релиза:

| Возможность | Production Telegram | Test Server | Решение для проекта |
|---|:-:|:-:|---|
| `sendWidget` в личном чате с ботом (`private`), запросы `WidgetQuery` и `editMessageWidgetData` | **Да** | Да | **Основной боевой контур продукта и демонстрации жюри** |
| Пересылка сообщений с виджетами (`protect_content` включается автоматически) | Нет | Да | Для шеринга плана другу используем кнопку/ссылку `/join/{token}` или открытку маршрута, а не пересылку самого пузыря с виджетом |
| Виджеты в группах, inline-режиме (`InputWidgetMessageContent`) и `sendSharedWidget` | Нет | Да | В production-группах используем обычные сообщения + новые `ephemeral_message_parameters` из Bot API 10.4 |

### Защита от старых версий клиентов Telegram

Клиенты Telegram, не обновлённые до поддержки Bot API 10.4, отображают сообщение с виджетом как *Unsupported media* вместе с его подписью (`caption`) и inline-клавиатурой (`reply_markup`). Поэтому **каждый вызов `sendWidget` в нашем адаптере обязан передавать**:

1. содержательный `caption` (краткая текстовая сводка условий или слотов дня со статусами);
2. `reply_markup` с компактной кнопкой открытия полной веб-поверхности / Mini App и резервным действием.

Таким образом, даже на устаревшем клиенте или при отключённом JS пользователь сохраняет 100% доступ к проверенному маршруту.

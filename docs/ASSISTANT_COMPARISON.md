# Сравнение правил и LLM

Из корня репозитория установите зависимости и прогоните правила и fallback на синтетическом каталоге.

```bash
npm --prefix backend ci
node backend/node_modules/tsx/dist/cli.mjs backend/scripts/compare-assistant.ts
```

Для живого прогона нужен OpenAI-совместимый API с поддержкой вызовов функций. Запишите конфигурацию в локальный `.env.llm`.

```dotenv
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
LLM_COST_IN_RUB_PER_1K=
LLM_COST_OUT_RUB_PER_1K=
```

`LLM_BASE_URL` — базовый адрес API без `/chat/completions`. Укажите фактические тарифы провайдера в рублях за 1000 входных и выходных токенов. `ASSISTANT_DAILY_BUDGET_RUB` по умолчанию загружается из конфигурации бэкенда. Живой прогон отправляет синтетические запросы и данные карточек провайдеру и расходует его API-бюджет.

```bash
node --env-file=.env.llm backend/node_modules/tsx/dist/cli.mjs backend/scripts/compare-assistant.ts --live > /tmp/afisha-llm-eval.json
```

Оба режима используют маршрут `/api/v1/assistant/query` и одинаковый каталог из свежей локальной базы. Runner измеряет p95 от запроса к роутеру до чтения тела ответа, суммирует стоимость каждой реплики по токенам и тарифам и проверяет попадание в топ-5 и сохранение размеченных условий. В сравнении бюджета участвуют диалоги с известной стоимостью всех реплик. В отчёте видны число реплик, дошедших до модели, и число fallback. При смешанном ответе LLM и fallback подтверждение порога p95 внешней модели остаётся пустым. Проба с локальным имитатором провайдера проверяет HTTP 503 → `rules-fallback-v2` с корректной карточкой.

`textFactualAccuracy` остаётся `null`. Для ручной проверки откройте `details[].turns`, выпишите утверждения ответа о названии, площадке, цене, возрасте, дате и статусе. Сверьте каждое утверждение с каталогом и `occurrence_id`. Отдельно отметьте неподтверждённые и неверные утверждения. При сравнении движков используйте одну рубрику и скройте имя движка от разметчика.

Позже добавлены три диалога с уточнением и случай без подходящих событий. В текущем наборе оба движка можно прогнать на 27 одинаковых сценариях. Реальный замер LLM ожидает конфигурацию провайдера.

Из прежних расхождений исправлены `TXT-007` и `TXT-008`. Три прежних расхождения касаются названия произведения, прошедшей даты и статуса. При точном сравнении теперь также учитываются лишние слоты. Оно выявило четыре случая, которые уже влияли на F1.

- `TXT-002` — название «Ревизор» распознано. Для присвоения категории конкретному произведению нужна однозначная запись каталога или справочника.
- `AMB-008` — ассистент уточняет будущую дату и удаляет прошедшую дату из поисковых фильтров. В корпусе ожидается извлечённое значение прошедшей даты.
- `SAFE-009` — поиск применяет статус по умолчанию `scheduled` или `rescheduled` и показывает допущение. В корпусе ожидается явное ограничение `scheduled` в извлечённых слотах.

- `CAT-007/008` — театр и кино должны влиять на порядок результатов. Сейчас они сужают выборку как жёсткие категории.
- `GEO-007/008` — упоминание оперного театра обозначает площадку. Сейчас оно сужает выборку до категории спектаклей.

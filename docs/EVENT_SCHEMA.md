# Схема события, контракт v1

Главный файл — [`contracts/event.schema.json`](../contracts/event.schema.json) (JSON Schema 2020-12). Этот документ объясняет правила. Если документ и схема расходятся, права схема, а документ нужно исправить в том же PR.

Основание: ТЗ п. 8.1 («Схема события»), п. 6.1 (статусы, спорные карточки), п. 6.3 (дедупликация, список источников). Схема используется одинаково в ответах API, в инструментах агента и в отображении на сайте и в боте.

## Поля п. 8.1

Все поля ниже **обязательны и всегда присутствуют** в ответе API. Если значение неизвестно и `null` разрешён, передаётся `null`, поле не пропускается.

| Поле | Тип JSON | null | Правило |
|---|---|---|---|
| `id` | string, uuid | нет | Непрозрачный идентификатор, клиент его не разбирает |
| `title` | string | нет | Название как у источника |
| `normalized_title` | string | нет | Нижний регистр, ё→е, без кавычек и лишних пробелов |
| `category` | enum | нет | `concert`, `performance` (спектакль), `exhibition`, `festival`, `cinema` (кино), `excursion`, `other` — ровно 7 |
| `tags` | string[] | нет | Метки: «джаз», «дети», «бесплатно», «башкирский язык». Нет меток — `[]` |
| `date_start` | string, date-time | нет | С поясом: `2026-11-14T19:00:00+05:00`. Для серии — ближайший актуальный сеанс |
| `date_end` | string, date-time | да | Если известно |
| `duration_min` | integer ≥ 1 | да | Если известна |
| `city` | string | нет | Название для показа: «Уфа». Для фильтров есть `city_id` |
| `venue` | string | нет | Название площадки. Для фильтров есть `venue_id` |
| `address` | string | да | |
| `lat`, `lon` | number | да | Координаты, если известны |
| `description` | string | нет | Краткое описание. Это недоверенный текст источника |
| `price_min`, `price_max` | integer ≥ 0 | да | Рубли. `0` — бесплатно. **`null` — цена не указана, это не бесплатно** |
| `is_free` | boolean | нет | `true` только по явной пометке источника |
| `age_limit` | 0, 6, 12, 16, 18 | да | `null` — не указано, это не «0+» |
| `language` | string | да | Код ISO 639: `ru`, `ba`, `tt` |
| `org_link` | string, uri | да | Организатор или билеты |
| `source_url` | string, uri | нет | Основной источник |
| `source_type` | enum | нет | `manual`, `import`, `rss`, `api`, `page` |
| `source_hash` | string | нет | SHA-256 исходной записи, 64 hex-символа в нижнем регистре |
| `verified_at` | string, date-time | да | Когда источник проверен; `null` — не проверялся |
| `confidence` | number 0..1 | нет | Уверенность извлечения |
| `status` | enum | нет | `published`, `draft`, `cancelled` |
| `dedup_key` | string | нет | Ключ дедупликации, см. ниже |
| `created_at`, `updated_at` | string, date-time | нет | Служебные |

## Правила

### Цена

| Данные | `price_min` | `price_max` | `is_free` | Показ |
|---|---|---|---|---|
| Источник явно пишет «бесплатно», «вход свободный» | 0 | 0 | true | «Бесплатно» |
| Одна цена 500 ₽ | 500 | 500 | false | «500 ₽» |
| «от 300 до 800 ₽» | 300 | 800 | false | «от 300 до 800 ₽» |
| Цена не указана | null | null | false | «Цена не указана» |

- `is_free = true` ⇒ `price_min = price_max = 0`. Проверяется схемой.
- `price_max = 0` ⇒ `is_free = true`, потому что «0 — бесплатно». Проверяется схемой.
- `price_min ≤ price_max`. Схема этого проверить не может, проверяет бэк при импорте.
- Если есть расширение `offers`, цены выводятся из общих билетов: тарифов без `audience` или с `audience = adult`. Детские и льготные тарифы на `price_min` и `price_max` не влияют.
- Фильтр `price_max=N` пропускает только события с известной ценой `price_min ≤ N`. Событие с `price_min = null` не проходит и учитывается в счётчике `hidden_unknown_price`.
- Фильтр `free=true` пропускает только `is_free = true`.

### Возраст

- `age_limit` — одно из 0, 6, 12, 16, 18. Показ: «6+». `null` — «Возраст не указан».
- Фильтр `age=N` (возраст посетителя) пропускает события с `age_limit ≤ N`. Событие с `age_limit = null` не проходит и учитывается в `hidden_unknown_age`.

### Дата, время и пояс

- Все даты в формате RFC 3339 с поясом. Регион живёт по `Asia/Yekaterinburg` (+05:00), отдавать время лучше в этом поясе.
- Расширение `time_precision`: `minute` (по умолчанию) или `date`. При `date` время неизвестно: в `date_start` стоит местная полночь `T00:00:00+05:00`, и время пользователю не показывается. Это же правило действует для каждого сеанса в `occurrences`.
- «Сегодня», «завтра», «выходные» сервер считает от своей текущей даты в поясе региона и возвращает её в `reference_date`.

### normalized_title

Нижний регистр, `ё` → `е`, убрать кавычки всех видов (`"`, `«`, `»`, `„`, `“`), схлопнуть подряд идущие пробелы, обрезать пробелы по краям.

Пример: `Демо-концерт «Ёлочные мелодии»` → `демо-концерт елочные мелодии`.

### dedup_key

`dedup_key = normalized_title | местная дата начала YYYY-MM-DD | venue_id`

Пример: `демо-концерт елочные мелодии|2026-12-19|demo-hall-1`.

- Разделитель `|` — рекомендация, которую нужно подтвердить с бэком. Состав ключа зафиксирован.
- Дата берётся из `date_start` в поясе региона, а не в UTC.
- Записи с одинаковым `dedup_key` сводятся в одну карточку. Все исходные записи попадают в расширение `sources`.

### source_hash и идемпотентный импорт

- `source_hash` — SHA-256 канонического представления исходной записи: для JSON — объект с отсортированными ключами, для CSV — строка после обрезки пробелов в ячейках.
- Повторная загрузка того же файла: каждая запись находится по `source_hash`, ничего не меняется, все записи попадают в счётчик `unchanged`.
- Новая версия записи (другой `source_hash`) с тем же `dedup_key` обновляет карточку: счётчик `updated`, источник добавляется в `sources`.

### confidence и verified_at

- Ручной ввод модератора и импорт файла заказчика: `confidence = 1`.
- Автоматическое извлечение (уровень 4): оценка парсера или модели. Карточка с низкой уверенностью уходит в очередь модерации, а не в выдачу.
- `verified_at` ставится, когда бэк проверил, что источник отвечает. До проверки — `null`.

### Статусы и видимость

| `status` | Список `GET /events` | `GET /events/{id}` | Админка |
|---|---|---|---|
| `published` | да | да | да |
| `cancelled` | нет | да, с явной пометкой «Отменено» | да |
| `draft` | нет | 404 `not_found` | да |

- Отменённое событие агент никогда не показывает как актуальное (ТЗ п. 9.2, метрика 11). На прямой вопрос «отменили ли?» агент отвечает по `GET /events/{id}`.
- Статусы сеансов в расширении `occurrences` уточняют расписание, но не заменяют `status` события. `status` события решает модерация.

### Спорные карточки

Расширение `review = { disputed, reasons }`. Карточка помечается спорной, если не хватает обязательных полей, цена или дата противоречат друг другу, есть возможный дубль или источник не отвечает. Примеры кодов причин: `missing_field`, `price_unknown`, `possible_duplicate`, `source_unreachable`, `date_in_past`. Спорные карточки видны в `GET /admin/moderation`.

### Заполненность карточки (метрика п. 9.1)

Предложение, согласовать с бэком. Карточка считается заполненной, если непусты: `title`, `category`, `date_start`, `city`, `venue`, `address`, `description`, `source_url`, а цена известна (`price_min` не `null` или `is_free = true`) и указан `age_limit`.

## Расширения

П. 8.1 разрешает расширять схему. Все расширения **необязательны**: потребитель обязан работать, если их нет.

| Поле | Тип | Правило |
|---|---|---|
| `city_id`, `venue_id` | slug | Коды справочников `GET /cities`, `GET /venues`. По ним работают фильтры |
| `time_precision` | `minute` \| `date` | См. «Дата, время и пояс» |
| `occurrences[]` | объект | `{ id, date_start, date_end, time_precision, status, status_verified, previous_date_start?, availability, is_past }`. Статус: `scheduled`, `cancelled`, `postponed`, `rescheduled`, `unknown`. Наличие: `available`, `sold_out`, `unknown`. `sold_out` — не отмена |
| `offers[]` | объект | `{ name?, price, audience?, is_free }`. `price` в рублях или `null`. `audience`: `adult`, `child`, `reduced`; без поля — общий билет |
| `sources[]` | объект | `{ source_url, source_type, source_hash, verified_at, title? }`. Все источники после дедупликации, первый совпадает с `source_url`. Это блок «Источники» в карточке (п. 6.3) |
| `review` | объект | `{ disputed, reasons[] }` |
| `popularity` | integer 0..100 | Для `sort=popularity` |
| `organizer` | string \| null | Название организатора |
| `kind` | enum | `standalone`, `performance_run`, `exhibition`, `festival` |
| `image` | string \| null | Путь или URL картинки. Alt по умолчанию строится из `title` |
| `title_ba` | string \| null | Название на башкирском из источника |
| `synthetic` | boolean | `true` у демо-событий |

Верхний уровень события не закрыт (`additionalProperties` не задан), чтобы переход сайта на контракт шёл постепенно. Но поля вне таблиц выше не входят в контракт: бэк не обязан их отдавать, а фронт и бот не должны на них опираться. Новое поле добавляется сначала в схему, потом в код.

## Сырые записи

ТЗ п. 6.1 требует хранить сырые данные отдельно от нормализованных, чтобы нормализацию можно было переиграть без повторного сбора. Это устройство базы, наружу оно не отдаётся. Минимум для таблицы сырых записей: `source_url`, `source_type`, `source_hash`, исходное содержимое как есть, время получения, `import_id`. Нормализованная карточка ссылается на свои сырые записи.

## Формат импорта

Метод: `POST /api/v1/admin/imports`, описание и отчёт — в [`contracts/api.openapi.yaml`](../contracts/api.openapi.yaml).

**JSON** — массив объектов `EventImportRecord`: те же имена полей, что в событии.

**CSV** — предложение, согласовать с бэком:

- UTF-8, разделитель — запятая, первая строка — имена полей п. 8.1;
- `tags` — через `;`;
- пустая ячейка — `null`;
- даты — как в JSON, с поясом.

Обязательные поля записи: `title`, `category`, `date_start`, `city`, `venue`, `source_url`. Сервер сам вычисляет `id`, `normalized_title`, `dedup_key`, `created_at`, `updated_at`, а также `source_hash`, если его нет. Запись с ошибкой не ломает весь импорт: она попадает в `rejected` с номером строки, кодом и понятной причиной.

Примеры кодов отказа: `missing_field`, `invalid_date`, `invalid_category`, `invalid_price`, `invalid_age_limit`, `invalid_url`.

# Telegram-бот афиши

Отдельный сервис-адаптер к REST API v1. Бот не ходит в базу и не содержит бизнес-логики каталога: всё, что он показывает, приходит из API. Работает через long polling, входящий порт ему не нужен.

Реализован **уровень 1 ТЗ** и расширенная карточка события. Поиск, карточка, сеансы, тарифы, календарь, фильтры и подписки работают всегда. LLM внутри бота нет: ассистент — только адаптер к `POST /assistant/query` за флагом `ASSISTANT_ENABLED` (по умолчанию выключен), при недоступности метода бот молча возвращается к обычному поиску.

## Быстрый старт

Нужен Node.js 22+.

```bash
cd bot
npm ci
cp .env.example .env       # вписать TELEGRAM_BOT_TOKEN
npm run build
npm start
```

Для разработки: `npm run dev` (tsx watch).

Проверки:

```bash
npm run check              # typecheck + 202 теста + build
npm run typecheck          # tsc по src и test
npm test                   # 202 теста в 12 файлах
npm run build
npm run smoke              # проверка живого API, нужен запущенный бэкенд
```

`npm run check` — то же, что выполняет CI в `.github/workflows/bot.yml` на push и pull request. CI не требует секретов и не ходит в живой API: все тесты работают на заглушках.

Docker:

```bash
cd bot
cp .env.example .env
docker compose up --build
```

В compose бот по умолчанию ходит на `http://host.docker.internal:8000`; если бэкенд в том же compose, задайте `API_BASE_URL=http://api:8000`. Брендовый жетон для `/start` лежит в `assets/token-height.png` и копируется в образ.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | да | — | Токен от @BotFather. В репозиторий и логи не попадает. |
| `API_BASE_URL` | нет | `http://localhost:8000` | Адрес REST API v1 без `/api/v1` на конце. |
| `API_TIMEOUT_MS` | нет | `10000` | Таймаут запросов к API. |
| `API_RETRY_ATTEMPTS` | нет | `2` | Сколько раз повторять GET при сети, таймауте, 429 и 5xx. `0` выключает повторы. POST/DELETE не повторяются. |
| `LOG_LEVEL` | нет | `info` | `debug`, `info`, `warn`, `error`. Логи — JSON в stdout. |
| `PUBLIC_WEB_URL` | нет | — | Публичный адрес сайта для кнопок «Открыть сайт» и «На сайте». `localhost` и приватные адреса отбрасываются: Telegram не принимает такие URL в inline-кнопках. |
| `SESSION_TTL_MINUTES` | нет | `120` | Сколько живёт состояние диалога без активности. |
| `CALLBACK_TTL_MINUTES` | нет | `720` | Сколько живут callback-токены inline-кнопок. |
| `RATE_LIMIT_PER_MINUTE` | нет | `20` | Лимит действий на пользователя в минуту. `0` выключает лимит. |
| `LOG_HASH_SECRET` | нет | токен бота | Ключ HMAC для псевдонимов пользователя в логах. Смена ключа разрывает корреляцию старых и новых логов. |
| `USER_REF_SECRET` | нет | `LOG_HASH_SECRET` → токен | Ключ HMAC для `user_ref` подписок. Смена ключа делает старые подписки невидимыми — это pre-release изменение. |
| `USER_REF_MODE` | нет | `hmac` | `hmac` — непредсказуемый `user_ref`; `legacy` — откат к `telegram_00000123`. |
| `ASSISTANT_ENABLED` | нет | `0` | Включает адаптер `POST /assistant/query`. При 404/503/таймауте бот возвращается к обычному поиску. |
| `ASSISTANT_CONFIRMATIONS` | нет | `0` | Подтверждения ассистента. Не включать до исправления P0-4 в PR #19: токен подтверждения не привязан к `user_ref`. |
| `BRAND_IMAGE_PATH` | нет | `assets/token-height.png` | Картинка-жетон для `/start`. `off` — отправлять приветствие без картинки. |

Токен читается только из окружения. Временный env-файл при проверке лежал вне репозитория с правами `600`.

## Что умеет

### Меню и справка

- `/start` — короткое приветствие, дисклеймер «неофициальный сервис» и главное меню. По умолчанию приходит картинкой-жетоном; если картинка недоступна, бот отправит тот же текст без неё.
- Команды зарегистрированы в меню Telegram: при вводе «/» видны основные разделы и фильтры.
- `/menu` — главное меню без приветствия.
- `/help` — справка по сценариям и командам.
- `/about` — о сервисе: кто делает, откуда данные, почему бот не продаёт билеты.
- `/cancel` — выйти из текущего сценария и вернуться в меню.

### Поиск и карточка

- Свободный текст — поиск по названию, описанию, площадке и тегам. Запрос длиннее 100 знаков обрезается, об этом сообщается в выдаче.
- `/find <текст>` — то же самое одной командой.
- Выдача — по 5 событий, с нумерацией, ценой, возрастом и свежестью данных. Кнопки под сообщением открывают карточку или следующую страницу.
- «Показать ещё», «Назад» и «В начало» не сбрасывают фильтры и не возвращают в меню.
- Карточка: категория, возраст, длительность, название, статус (отменено/перенесено/не подтверждено), дата и время, город, площадка, адрес, цена или «бесплатно», наличие билетов, язык, теги, организатор, описание, источник и время проверки. Демонстрационные события помечаются явно.
- «📅 Все сеансы» — полный список дат и времён события с ценами и статусами; в карточке по умолчанию показывается ближайший подходящий сеанс.
- «🎟 Тарифы» — все предложения с ценой и аудиторией (взрослый, детский, льготный), включая бесплатные.
- «🗓 В календарь» — файл `.ics` с выбранным сеансом (или всеми сеансами события). Время переводится из `Asia/Yekaterinburg` в UTC, отменённые сеансы помечаются в календаре. Скачивается файлом, ничего не сохраняет на сервере.
- «📍 На карте» — ссылка на карты по адресу площадки; «📤 Поделиться» — ссылка на событие на сайте или в боте.
- Deep link `https://t.me/<bot>?start=event_<uuid>` открывает карточку события напрямую. Невалидный payload не ломает `/start`: бот показывает обычное приветствие.
- «🎯 Похожие» — список событий той же категории или с общими метками через `GET /events/{id}/similar`. Если метод ещё не задеплоен (404) или вернул пусто, бот показывает понятное сообщение и меню, а не ошибку.
- «🏛 Расписание площадки» — ближайшие две недели площадки через `GET /venues/{id}/schedule`. Если метода нет, кнопка честно сообщает, что расписание недоступно.
- В выдаче бот честно пишет, сколько событий скрыто фильтром из-за неизвестной цены или возраста: «Ещё N: цена не указана…» / «Ещё N: возраст не указан…».
- «🎟 Билеты» и «🌐 Источник» — раздельные кнопки. Если ссылки совпадают, остаётся одна. `javascript:`, `localhost`, приватные IP и placeholder-домены в кнопки не попадают.
- Если `PUBLIC_WEB_URL` публичный, в карточке появляется кнопка «🌐 На сайте» со ссылкой на `events/{uuid}`.

### Фильтры

- `/filters` или кнопка «🎛 Фильтры» — экран фильтров текущего поиска.
- Дата: сегодня, завтра, выходные, неделя, конкретный день из ближайших 10 (`/date 2026-11-20`) или период `2026-11-20..2026-11-25`. Конкретные дни считаются в часовом поясе афиши (`Asia/Yekaterinburg`), поэтому сервер в UTC не сдвигает «сегодня» на вчера.
- Цена: бесплатно или потолок `500`, `1 000`, `2 000`, `3 000`, `5 000 ₽` (`/price free`, `/price 1000`).
- Возраст: `0+`, `6+`, `12+`, `16+`, `18+` (`/age 6`). Это возраст посетителя для фильтра `age`, а не возрастной рейтинг события; в подписи так и написано: «6 лет».
- Язык: русский, башкирский, татарский, английский (`/language ba`).
- Сортировка: по дате или по цене (`/sort price`).
- Город и категория: отдельные экраны выбора (`/city Уфа`, `/category концерты`).
- Каждое нажатие сразу применяет фильтр и перезапрашивает выдачу. «Сбросить» убирает фильтры, но сохраняет текст запроса.
- Пустая выдача объясняет, что не найдено, и предлагает снять конкретный фильтр: цену, дату, возраст, язык, категорию, город или сам запрос.
- Если API прислал `relaxations`, бот показывает серверные варианты ослабления с количеством событий и применяет их одним нажатием. Если счётчиков `facets` нет (старый бэкенд), фильтры работают как раньше.
- Команды `/today`, `/tomorrow`, `/weekend`, `/week`, `/date`, `/city`, `/category`, `/price`, `/age`, `/language`, `/sort` работают и как обычные фильтры, и как быстрый старт поиска.

### Подписки

- «🔔 Подписаться» в карточке — быстрая подписка на город и категорию события.
- «➕ Новая подписка» — конструктор: город, категория и период, любой пункт можно оставить «Любой».
- «Мои подписки» (`/subscriptions`, `/unsubscribe`) — список и удаление кнопкой.
- «▶️» у подписки открывает подходящие события: город, категория и период подставляются в поиск.
- Повторная подписка и уже удалённая подписка обрабатываются понятными сообщениями, а не ошибкой API.

Подписки хранятся в бэкенде. Бот только создаёт, показывает и удаляет их через API; доставку уведомлений по подпискам уровень 1 не обещает. `user_ref` подписок — HMAC-псевдоним от Telegram id (`USER_REF_MODE=hmac`, по умолчанию). Старые подписки с `telegram_<id>` после переключения не находятся; для отката предусмотрен `USER_REF_MODE=legacy`.

### Ассистент (за флагом)

- `ASSISTANT_ENABLED=1` включает адаптер к `POST /assistant/query`: свободный текст уходит ассистенту вместо обычного поиска. Сообщение ассистенту допускается до 1000 знаков; обычный поиск по-прежнему обрезается до 100.
- Бот показывает ответ, карточки результатов, причины выбора, допущения, счётчики скрытых событий, серверные ослабления и быстрые ответы на уточнения.
- «Что учёл» объясняет, как ассистент понял запрос; условия можно снимать кнопками-чипами, а кнопка «🔎 Обычный поиск» всегда возвращает к поиску по API.
- История диалога и `constraints` живут в памяти сессии; в запрос уходят последние 12 реплик, как в контракте.
- Своей LLM и своего NLU у бота нет: если метод отсутствует (404/405), вернул 400/5xx, не совпал с контрактом или API недоступен, бот мягко откатывается на обычный поиск. При 429 бот просит подождать и не обходит лимит.
- Подтверждения действий (`ASSISTANT_CONFIRMATIONS=1`) реализованы, но по умолчанию выключены: в PR #19 токен подтверждения не привязан к `user_ref`. Включать только после исправления P0-4.

### Справочники

Города и категории бот не хранит у себя как источник истины: при старте он запрашивает `GET /cities` и `GET /categories` и держит их в памяти. Встроенный список (`directory-service.ts`) используется только как fallback, если API недоступен или вернул пустой ответ, — бот всё равно поднимется. Новый город или категория, добавленные в бэкенде, появляются в боте после перезапуска без правок кода. Длинные справочники листаются по 24 элемента, чтобы не упереться в лимит кнопок Telegram.

## Надёжность и безопасность

- **Inline-кнопки не доверяют `callback_data`.** В кнопке лежит только случайный токен `v1_<12 base64url>`, а действие хранится в памяти бота. Токен привязан к `user_id`, живёт 12 часов по умолчанию и не содержит id события, подписки или названия действия.
- **Устаревшая кнопка** (после рестарта или истечения TTL) получает ack и свежее меню с объяснением, а не молчание.
- **HTML-разметка.** Все данные API и пользовательский ввод проходят через `escapeHtml`; иначе название события с `<` сломало бы сообщение.
- **Лимит частоты.** По умолчанию 20 действий в минуту на пользователя; для callback показывается alert с просьбой подождать.
- **Ошибки API** показываются нейтральным текстом и коротким кодом обращения. В лог уходят `X-Request-Id`, статус и код ошибки, но не токен и не сырой Telegram id.
- **Повторы GET.** Сетевые ошибки, таймауты, 429 и 5xx повторяются с backoff (`API_RETRY_ATTEMPTS`, по умолчанию 2). `Retry-After` учитывается: если сервер просит ждать дольше 5 секунд, бот не держит обработчик, а сразу показывает паузу. POST и DELETE не повторяются, чтобы не создать дубль подписки.
- **Кеш карточек.** `getEvent` держит ETag-кеш: в течение 60 секунд повторный просмотр карточки не ходит в сеть, после — ревалидация `If-None-Match`; `304` отдаёт кеш и продлевает TTL, `200` обновляет данные. Лимит 200 карточек, вытеснение по переполнению. Изменение события на бэкенде меняет ETag — бот подхватит его не позже, чем через минуту.
- **Пользователь в логах** — только HMAC-псевдоним вида `u_ab12cd34ef56` (ключ — `LOG_HASH_SECRET` или токен бота); `user_ref` и Telegram id туда не пишутся.
- **Ссылки** проходят через `telegramSafeHttpUrl`: только `http(s)`, без логина/пароля, localhost, `.local`, приватных IPv4/IPv6 и placeholder-доменов.
- **Состояние диалога и callback-токены живут в памяти** процесса. После рестарта поиск и черновик подписки сбрасываются, старые кнопки становятся stale; подписки при этом остаются в бэкенде.

## Как устроен

```
src/
  index.ts          точка входа: конфиг, клиент, long polling
  bot.ts            команды, сценарии, callback-и, live-логи
  callback-store.ts непрозрачные callback-токены: TTL, привязка к пользователю
  rate-limit.ts     лимитер действий на пользователя
  api/client.ts     HTTP-клиент, повторы GET, X-Request-Id и ApiError
  api/types.ts      zod-схемы ответов API
  calendar.ts       .ics: UTC, события на весь день, экранирование
  format.ts         карточки, выдача, сеансы, тарифы, площадка, ассистент, HTML-escaping
  keyboards.ts      inline-клавиатуры
  callbacks.ts      типы действий кнопок
  session.ts        in-memory состояние диалога и ассистента
  directory-service.ts справочники из API, fallback и поиск города/категории
  search-options.ts даты, пресеты, возраст, язык и ценовые пороги
  texts.ts          тексты интерфейса
  user-ref.ts       стабильный user_ref (HMAC) и хеш для логов
  smoke.ts          smoke-проверка API
assets/
  token-height.png  брендовый жетон для /start
```

- `user_ref` по умолчанию — HMAC от Telegram id (`u_…`), стабилен между перезапусками при том же секрете. `USER_REF_MODE=legacy` возвращает формат `telegram_00000123` для отката.
- Состояние диалога (текущий поиск, черновик подписки, контекст ассистента) живёт в памяти процесса. После рестарта оно сбрасывается, подписки при этом остаются в бэкенде.
- `CallbackStore` после рестарта пуст: это ожидаемое поведение, а не потеря данных.

## Используемые методы API

| Метод | Назначение |
| --- | --- |
| `GET /api/v1/events` | поиск, срезы, пагинация, `price_max`, `free`, `age`, `language`, `sort`, `date`, `date_from`/`date_to` |
| `GET /api/v1/events/{id}` | карточка события |
| `GET /api/v1/events/{id}/similar` | похожие события; при 404 бот мягко откатывается к меню |
| `GET /api/v1/venues/{id}/schedule` | расписание площадки на две недели; при отсутствии метода — понятное сообщение |
| `GET /api/v1/cities` | справочник городов при старте |
| `GET /api/v1/categories` | справочник категорий при старте |
| `GET /api/v1/subscriptions` | список подписок |
| `POST /api/v1/subscriptions` | создание подписки |
| `DELETE /api/v1/subscriptions/{id}` | удаление подписки |
| `POST /api/v1/assistant/query` | адаптер ассистента за флагом; при недоступности — обычный поиск |
| `POST /api/v1/assistant/confirm` | подтверждение действия; только при `ASSISTANT_CONFIRMATIONS=1` |

## Ограничения

- **Уведомления по подпискам не доставляются**: в бэкенде нет воркера рассылки. Бот не обходит это и не шлёт сообщения сам.
- Ассистент выключен по умолчанию и требует `POST /assistant/query` в бэкенде (PR #19). Без метода бот работает как обычный поиск.
- Подтверждения ассистента выключены до исправления P0-4 в PR #19: токен не привязан к `user_ref`.
- «Похожие» требуют метода `GET /events/{id}/similar` в бэкенде. Пока его нет в `main`, кнопка есть, но обработчик отвечает «Похожие события сейчас недоступны» и не ломает диалог.
- Расписание площадки требует `GET /venues/{id}/schedule`; без метода показывается понятное сообщение.
- Нет хранения состояния между рестартами; для горизонтального масштабирования понадобится внешний session store и общее хранилище callback-токенов.
- Справочники городов и категорий обновляются при старте. Если API недоступен, до следующего перезапуска работает встроенный fallback-список.
- `PUBLIC_WEB_URL` должен быть публичным: локальный адрес намеренно не попадает в кнопки.
- Живой прогон после последних изменений ещё не выполнен.

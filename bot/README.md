# Telegram-бот афиши

Отдельный сервис-адаптер к REST API v1. Бот не ходит в базу и не содержит бизнес-логики каталога: всё, что он показывает, приходит из API. Работает через long polling, входящий порт ему не нужен.

Реализован **уровень 1 ТЗ**: поиск, карточка события, пагинация, подписки, справка и отмена сценария. LLM и `POST /assistant/query` не используются.

## Быстрый старт

Нужен Node.js 22+.

```bash
cd bot
npm ci
cp .env.example .env       # вписать TELEGRAM_BOT_TOKEN
npm run build
npm start
```

Для разработки: `npm run dev` (tsx watch).

Проверки:

```bash
npm run typecheck          # tsc по src и test
npm test                   # 71 тест в 7 файлах
npm run build
npm run smoke              # проверка живого API, нужен запущенный бэкенд
```

Docker:

```bash
cd bot
cp .env.example .env
docker compose up --build
```

В compose бот по умолчанию ходит на `http://host.docker.internal:8000`; если бэкенд в том же compose, задайте `API_BASE_URL=http://api:8000`.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | да | — | Токен от @BotFather. В репозиторий и логи не попадает. |
| `API_BASE_URL` | нет | `http://localhost:8000` | Адрес REST API v1 без `/api/v1` на конце. |
| `API_TIMEOUT_MS` | нет | `10000` | Таймаут запросов к API. |
| `LOG_LEVEL` | нет | `info` | `debug`, `info`, `warn`, `error`. Логи — JSON в stdout. |
| `PUBLIC_WEB_URL` | нет | — | Публичный адрес сайта для кнопки «Открыть на сайте». `localhost` и приватные адреса отбрасываются: Telegram не принимает такие URL в inline-кнопках. |

Токен читается только из окружения. Временный env-файл при проверке лежал вне репозитория с правами `600`.

## Что умеет

- `/start` — приветствие и главное меню.
- `/help` — справка по сценариям и командам.
- `/cancel` — выйти из текущего сценария и вернуться в меню.
- Свободный текст — поиск по названию, описанию, площадке и тегам.
- «Показать ещё» — постраничная выдача, по 5 событий.
- Карточка события — дата и время, город и площадка, цена, возраст, длительность, теги, описание, предупреждения об отмене/переносе и пометка синтетических данных.
- «Ближайшие», «Категории», «Города» — готовые срезы каталога.
- Подписка из карточки — город и категория события в один клик.
- Конструктор подписки — город, категория и период; можно оставить «Любой».
- «Мои подписки» — список и удаление.

Подписки хранятся в бэкенде. Бот только создаёт, показывает и удаляет их через API; доставку уведомлений по подпискам уровень 1 не обещает.

## Как устроен

```
src/
  index.ts        точка входа: конфиг, клиент, long polling
  bot.ts          команды, сценарии, callback-и, live-логи
  api/client.ts   HTTP-клиент и ApiError
  api/types.ts    zod-схемы ответов API
  format.ts       карточки, выдача, подписки, безопасные URL
  keyboards.ts    inline-клавиатуры
  callbacks.ts    формат callback-данных и разбор
  session.ts      in-memory состояние диалога
  dictionaries.ts справочники городов и категорий
  texts.ts        тексты интерфейса
  user-ref.ts     стабильный user_ref
  smoke.ts        smoke-проверка API
```

- `user_ref` = `telegram_<id с padding до 8 цифр>`, например `telegram_08646716020`. Формат стабилен между перезапусками.
- Состояние диалога (текущий поиск, черновик подписки) живёт в памяти процесса. После рестарта оно сбрасывается, подписки при этом остаются в бэкенде.
- Ссылки в inline-кнопках проходят через `telegramSafeHttpUrl`: только `http(s)`, без `localhost`, `.local` и приватных IPv4. Иначе Telegram отклоняет всё сообщение.
- Ошибки API показываются пользователю нейтральным текстом, детали пишутся в лог без токена.

## Используемые методы API

| Метод | Назначение |
| --- | --- |
| `GET /api/v1/events` | поиск, срезы, пагинация |
| `GET /api/v1/events/{id}` | карточка события |
| `GET /api/v1/subscriptions` | список подписок |
| `POST /api/v1/subscriptions` | создание подписки |
| `DELETE /api/v1/subscriptions/{id}` | удаление подписки |

## Ограничения

- Только уровень 1: нет ИИ-ответов, рекомендаций и доставки уведомлений по подпискам.
- Нет хранения состояния между рестартами; для горизонтального масштабирования понадобится внешний session store.
- `PUBLIC_WEB_URL` должен быть публичным: локальный адрес намеренно не попадает в кнопки.

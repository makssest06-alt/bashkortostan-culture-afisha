# Регрессия поиска по фиксированному каталогу

`catalog.fixture.json` содержит 15 синтетических событий из схемы API. `relevance.fixture.jsonl` содержит 27 открытых сценариев, включая четыре двухрепликовых диалога. Авторы используют этот набор при разработке. Для оценки на независимых запросах нужен отдельный набор от проверяющих.

Сценарии используют `reference_now` и часовой пояс каталога `Asia/Yekaterinburg`. `qrels` связывает ID события с оценкой 2 (подходит) или 1 (запасной вариант при мягком предпочтении). Отсутствующий ID означает 0 внутри этого снимка. У каждого события один сеанс. Квесты представлены категорией `other` с названием или тегом «квест» согласно доступным категориям API.

`expected_hard` задаёт проверяемые ограничения. Для диалога `previous_query` содержит первую реплику, а `query` следующую. Runner передаёт состояние из фактического первого ответа. Поле `expected_first_clarify` задаёт ожидаемую тему первого уточнения.

Hit@5, Precision@5 и Recall@5 используют оценку 2. nDCG@5 учитывает обе положительные оценки. Пороги для разработки — Hit@5 ≥ 90%, пустая выдача при наличии подходящего ≤ 5%, ноль нарушений размеченных условий и ноль отменённых сеансов в обычной выдаче. Замер сравнивает дату, статус и время конкретного сеанса, а также цену, город и возраст в карточке. Произвольный текст ответа требует проверки утверждений человеком.

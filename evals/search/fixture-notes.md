# Synthetic search regression fixture

`catalog.fixture.json` is a fixed synthetic closed-world snapshot of 15 API Event objects; no event is real. `relevance.fixture.jsonl` has 23 visible developer-authored regression requests and event-level relevance labels. This is not an independent acceptance set, and it does not establish real-world search quality. Gather a separate, independently authored and human-reviewed holdout of real or representative requests, including multi-turn sessions, before using the numbers for acceptance.

Every request is evaluated at `reference_now` in the given timezone. `qrels` maps event IDs to grades: 2 directly satisfies the request, 1 is an acceptable alternative for an explicitly soft preference, and an omitted catalog ID has grade 0. Labels cover the entire fixed catalog and must not be reused with another snapshot. A result is identified by event ID, not occurrence ID; every fixture event has one occurrence. The follow-up RQ-016 includes `previous_query` and `previous` in assistant constraints format `{hard, soft}`; evaluate with that prior state, not as an isolated query. `expected_hard` captures selected independently checkable constraints, not a complete semantic interpretation. RQ-022/023 use category `other` with a quest tag because the API contract has no quest category.

Report Recall@5 (grades >= 1), nDCG@5 (gain `2^grade - 1`), and per-case output, along with hard-constraint violations. These are proposed development gates: mean Recall@5 >= 0.80, mean nDCG@5 >= 0.75, and zero hard-constraint violations; they require product and independent reviewer agreement before acceptance. Do not infer latency or production quality from this small synthetic fixture. Report empty result cases and parsing failures as failures, rather than dropping them. Grades, thresholds and case selection have not been independently human-validated.

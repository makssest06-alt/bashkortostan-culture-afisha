# scene-kit: контракт сцен главной

Главная это 15 сцен подряд. Каждая сцена живёт в своём каталоге `src/components/home/scenes/<id>/`
и состоит из двух файлов:

- `def.ts`: описание сцены (длина закрепления, поза жетона, свечение, цвет шапки);
- `index.tsx`: компонент сцены, экспорт по умолчанию, рендерит `<Scene def={def}>`.

Порядок сцен и стыки между ними задаёт `scene-kit/registry.ts`, компоненты собраны в `scenes/index.ts`.
Автор сцены правит только свой каталог `scenes/<id>/`. Файлы `scene-kit/**`, `scenes/index.ts`,
`HomeStage.tsx` и `scenes/_stub/**` общие: их не трогать.

Порядок: intro, hero, ai, gallery, fullscreen, thermal, blueprint, wordmark, filters, dedup, trust,
cities, popular, choose, footer.

## Слои страницы

Снизу вверх (z-index из `globals.css`):

| слой | что это | кто управляет |
|---|---|---|
| `--z-bg` 0 | фиксированный фон со свечением `.glow-bg` | поле `glow` в def |
| `--z-backdrop` 5 | подложки сцен ПОД жетоном | слот `backdrop` у `<Scene>` |
| `--z-token` 10 | холст с жетоном | поле `token` в def |
| `--z-content` 20 | содержимое сцен (`main`) | дети `<Scene>` |
| `--z-grain` 40, `--z-progress` 50, `--z-header` 60 | зерно, полоса прогресса, шапка | оболочка сайта |

Содержимое сцены всегда НАД жетоном. Непрозрачный фон сцены (фото на весь экран, кремовый блок)
закрывает жетон. Если что-то должно лежать под жетоном, это подложка (`backdrop`).

## Типы (`types.ts`)

```ts
type TokenPose = {
  x: number; y: number;   // смещение центра от центра окна в долях ширины и высоты:
                          // 0,0 = центр; x = 0.5 правый край; y = 0.5 нижний край
  scale: number;          // диаметр жетона в долях ШИРИНЫ окна (0.309 = 30,9 % W, как в спецификациях)
  rx: number; ry: number; rz: number;   // радианы, порядок Эйлера XYZ; при нулях жетон лицом к зрителю
  opacity: number;        // 0..1
  mode?: 'solid' | 'wire';              // медь (по умолчанию) или чертёж
};

type SceneEnv = { w: number; h: number; mobile: boolean; reduced: boolean };
// w, h: размер окна в px; mobile: ширина < 768; reduced: prefers-reduced-motion

type SceneDef = {
  id: string;
  pinVh: number;          // длина закрепления на компьютере, в экранах
  pinVhMobile?: number;   // на телефоне; не задано: как pinVh; 0: на телефоне обычный поток
  flow?: boolean;         // сцена всегда идёт обычным потоком
  token?: (p: number, env: SceneEnv) => TokenPose | null;
  headerTone?: 'light' | 'dark';        // цвет шапки: 'light' светлая (по умолчанию), 'dark' тёмная
  // необязательные дополнения каркаса:
  glow?: number | ((p: number, env: SceneEnv) => number);   // яркость свечения фона 0..1, по умолчанию 1
  enter?: 'cut' | 'scroll';             // как сцена входит после закреплённой сцены, по умолчанию 'cut'
  exit?: 'cut' | 'scroll';              // как выходит перед закреплённой сценой, по умолчанию 'cut'
};
```

`def.ts` импортирует только из `../../scene-kit/types` и `../../scene-kit/math`.
Импорт из `../../scene-kit` (общий index) в def.ts даст цикл с реестром и ошибку при загрузке.

## Закрепление и прогресс

**Закреплённая сцена** (`pinVh > 0`). Экран сцены `.scene-stage` высотой `100dvh` закрепляется:
`ScrollTrigger { pin: true, start: 'top top', end: '+=' + pinVh * 100 + '%', scrub: true, anticipatePin: 1,
invalidateOnRefresh: true }`. Локальный прогресс `p` идёт от 0 (экран встал) до 1 (закрепление кончилось).

**Сцена-поток** (`flow: true` или длина 0). Закрепления нет, высота секции по содержимому.
`p = 0`, когда верх секции показался снизу окна, `p = 1`, когда низ секции ушёл за верх окна.
У последней сцены страницы (footer) прогресс до 1 не доходит: страница кончается раньше.

На ширине меньше 768 берётся `pinVhMobile`. Сейчас в реестре (компьютер / телефон, в экранах):
intro 0.7 / 0.6, hero 2.8 / 2.2, ai 1.8 / 1.4, gallery 10 / 8, fullscreen 1.6 / 1.2, thermal 1.8 / 1.5,
blueprint 3.4 / 2.8, wordmark 2.8 / 2.2, filters 4.0 / 3.4, dedup 2.6 / 2.2, trust 3.6 / 2.8, cities поток,
popular 5.6 / 4.6, choose поток, footer поток. Темп выровнен: около 0,7 экрана прокрутки на один смысловой шаг
сцены на компьютере и около 0,57 на телефоне. Меняя длину, держите этот темп.

### Стыки сцен

- **Две закреплённые сцены подряд: склейка на месте** (`cut`). Перелистывания нет: в момент, когда
  кончилась сцена A, на её месте уже стоит сцена B. Экраны наложены друг на друга, виден только активный
  (каркас сам ставит `visibility: hidden` остальным). Поэтому в конце сцены уводите своё содержимое
  (последние 8-12 % прогресса), а в начале проявляйте: резкой смены тогда не видно.
- **Обычная прокрутка** (`scroll`): экран прошлой сцены уезжает вверх, следующая въезжает снизу.
  Так стыкуется любая сцена с потоком. Для двух закреплённых это включается полем `exit: 'scroll'`
  у первой или `enter: 'scroll'` у второй.
- У активной секции стоит атрибут `data-active`.

Прогресс считается из положения прокрутки напрямую, без сглаживания (то же, что `scrub: true`).
Плавность даёт Lenis. При `prefers-reduced-motion` Lenis выключен, закрепление и прогресс работают как обычно:
в сцене проверяйте `env.reduced` и заменяйте перемещения и повороты на проявление и затухание.

## `<Scene>`

```tsx
<Scene
  def={def}
  className="..."      // классы экрана сцены (.scene-stage)
  after={...}          // содержимое в обычном потоке сразу после закреплённого экрана (та же секция)
  backdrop={...}       // подложка ПОД жетоном: фиксированный слой на весь экран
  label="..."          // aria-label секции
>
  {children}
</Scene>
```

Разметка, которую рендерит каркас:

```html
<section class="scene" data-scene="hero" data-pin-d data-pin-m [data-active]>
  <div class="scene-stage ...className">   <!-- закрепляется; position: relative; 100dvh; overflow: clip -->
    ...children
  </div>
  ...after
</section>
```

- Экран `.scene-stage` это `position: relative`: абсолютные дети позиционируются от него.
- НЕ вешайте `transform`, `filter`, `opacity` и анимации GSAP на сам `.scene-stage` и на `<section>`:
  его двигает закрепление. Анимируйте детей.
- Не смешивайте на одном элементе классы Tailwind `translate-*`, `scale-*`, `rotate-*` и GSAP `x`, `y`,
  `scale`, `rotation`: в Tailwind v4 это отдельные CSS-свойства, они сложатся с transform от GSAP.
- `backdrop` рендерится порталом вне секции (в слой подложек) и только в браузере. Виден, пока сцена
  на экране (между началом и концом своего отрезка). Анимируйте содержимое подложки, а не сам её узел.

## Хуки (вызывать только внутри `<Scene>`)

### `useSceneTimeline((tl, ctx) => void, deps?)`

Создаёт `gsap.timeline` длиной ровно 1. Позиции и длительности пишутся в долях прогресса сцены.
Время таймлайна всегда равно прогрессу. Кривая по умолчанию `'none'`, можно задать свою на отдельном движении.

```ts
ctx = {
  root: HTMLElement,                 // <section> сцены
  env: SceneEnv,
  q: gsap.utils.selector(root),      // поиск только внутри секции: q('.title')
  backdrop: HTMLElement | null,      // узел подложки; он вне секции, q его не видит
}
```

- Работает через `useGSAP` с областью видимости секции: при размонтировании и пересборке всё откатывается.
- Пересобирается при смене окружения (ресайз, переход через 768px, смена «меньше движения») и при смене `deps`.
- Можно вызвать несколько раз в одной сцене: получится несколько независимых таймлайнов.
- Всё, что позже 1, не проиграется (в режиме разработки будет предупреждение в консоли).
- Вход пишите через `fromTo`, выход через `to`: два `fromTo` на одном свойстве одного элемента затрут друг друга.
- Пороговые эффекты: `tl.call(fn, [], 0.74)` (сработает при проходе в обе стороны) или `useSceneProgress`.
- До запуска скриптов страница показывает обычную вёрстку. Элементы первой сцены, которые появляются
  не сразу, прячьте стартовым классом `invisible`: `autoAlpha` перекроет его инлайном.

### `useSceneProgress((p, env) => void)`

Подписка на локальный прогресс без ререндеров React. Колбэк сразу получает текущее значение.
Для счётчиков, классов, порогов и цвета шапки.

### `useScene()`

Возвращает `{ def, env, layout, rootRef, backdrop }`. `layout = { index, pinned, pinVh, cutIn, cutOut }`
это раскладка сцены при текущей ширине.

## Жетон

Жетон один на всю страницу: фиксированный холст (`TokenCanvas`) между фоном и содержимым.
Позу задаёт поле `token` в def: функция от локального прогресса и окружения.

- На стыке сцен позы смешиваются: последние 8 % сцены A и первые 8 % сцены B, на самой границе 50 на 50.
- Нет `token` или функция вернула `null`: жетон плавно гаснет на месте.
- Холст дополнительно сглаживает движение, поэтому поза может меняться ступенями (пороги допустимы).
- Углы смешиваются как числа. Если сцена закончила с `ry = Math.PI`, следующей лучше начать с того же
  значения (так сделано в ai после hero), иначе на стыке жетон сделает лишний оборот.
- Без WebGL, на слабом устройстве и при «меньше движения» вместо холста работает плоский медный диск
  на CSS: место, размер и прозрачность те же, вращения нет. Проверка: `/?token=css`.
- Сама 3D-модель лежит в `src/components/three/Token.tsx`: медный жетон с рельефом курая и кускара (лицо) и надписью «АФИША 102» (оборот), диаметр 1, лицом к +Z. Режим `mode: 'wire'` рисует чертёж контуров.
- Оборот читается прямо при `ry = π`. Два полуоборота вокруг перпендикулярных осей разворачивают лицо на 180° в плоскости, поэтому после них нужен `rz = π` (так сделано в hero и ai).
- Без WebGL и при «меньше движения» показывается статичный рендер жетона `/images/token-fallback.webp` (CSS-заглушка ведётся той же позой без вращения).

Помощники из `scene-kit/math.ts`: `POSE` (жетон по центру), `span(p, from, to)` (доля пути внутри отрезка
прогресса), `lerp`, `smooth`, `clamp01`, `mixPose`.

```ts
// scenes/hero/def.ts
import { lerp, POSE, smooth, span } from '../../scene-kit/math';
import type { SceneDef } from '../../scene-kit/types';

export const def: SceneDef = {
  id: 'hero',
  pinVh: 1.4,
  pinVhMobile: 1.0,
  glow: (p) => span(p, 0.3, 1),                       // свечение разгорается с 30 % сцены
  token: (p, env) => ({
    ...POSE,
    y: env.mobile ? -0.1 : 0,
    scale: (env.mobile ? 0.56 : 0.309) * lerp(0.87, 1, smooth(span(p, 0, 0.25))),
    ry: env.reduced ? 0 : Math.PI * span(p, 0.25, 0.63),   // оборот вокруг вертикальной оси
    rx: env.reduced ? 0 : Math.PI * span(p, 0.63, 0.88),   // затем вокруг горизонтальной
  }),
};
```

## Свечение фона и цвет шапки

- **Свечение.** `glow` в def: число или функция прогресса, 0..1 (по умолчанию 1). На стыках смешивается
  так же, как поза жетона. Сам слой `.glow-bg` руками не анимировать.
- **Шапка.** `headerTone: 'dark'` в def делает шапку и полосу прогресса тёмными, пока сцена под шапкой.
  Если цвет меняется по ходу сцены, зовите `setHeaderTone(id, tone)`:

```ts
useSceneProgress((p) => setHeaderTone(def.id, p >= 0.74 ? 'dark' : 'light'));
```

  Значение действует, пока верх следующей сцены не дошёл до шапки. `setHeaderTone(id, null)` возвращает
  значение из def. Каркас пишет результат в `<html data-header-tone="light | dark">`.
- **Светлый блок.** Поставьте `data-theme="light"` на контейнер: `bg-bg`, `text-fg`, `border-line`,
  цвета статусов внутри переключатся на кремовую палитру сами.

## Стор (`store.ts`)

Изменяемый объект без состояния React. Обычно хватает хуков, напрямую он нужен редко.

```ts
sceneStore = { scenes, progressById, activeId, pageProgress, toneSceneId, headerTone }
getSceneProgress(id): number
subscribe(listener): () => void                 // любое изменение прогресса сцен
subscribeScene(id, (p) => void): () => void     // прогресс одной сцены, сразу отдаёт текущее значение
subscribePage((p) => void): () => void          // прогресс всей страницы 0..1
getTokenPose(env): TokenPose                    // поза жетона с учётом смешения на стыках
getGlow(env): number
setHeaderTone(id, 'light' | 'dark' | null): void
```

`activeId` это последняя по порядку сцена, которая уже началась (`p > 0`).

## Пример сцены

```tsx
// scenes/ai/index.tsx
'use client';

import { Scene, useSceneTimeline } from '../../scene-kit';
import { def } from './def';

function AiStage() {
  useSceneTimeline((tl, { q, env }) => {
    const rise = env.reduced ? 0 : 48;
    // вход после склейки: первые 12 % сцены
    tl.fromTo(q('.ai-title'), { autoAlpha: 0, y: rise }, { autoAlpha: 1, y: 0, duration: 0.12 }, 0.02);
    tl.fromTo(q('.ai-form'), { autoAlpha: 0 }, { autoAlpha: 1, duration: 0.1 }, 0.24);
    // плато, затем выход: последние 10 %
    tl.to(q('.ai-title, .ai-form'), { autoAlpha: 0, duration: 0.1 }, 0.9);
  });

  return (
    <div className="flex h-full flex-col items-center justify-center px-(--gutter)">
      <h2 className="ai-title t-display">Подберёт ИИ</h2>
      <form className="ai-form mt-10" action="/ask">...</form>
    </div>
  );
}

export default function AiScene() {
  return (
    <Scene def={def}>
      <AiStage />
    </Scene>
  );
}
```

Хуки сцены живут во внутреннем компоненте (`AiStage`), потому что им нужен контекст `<Scene>`.

## Телефон

- Закрепление работает так же, длины берутся из `pinVhMobile`.
- Панель адреса меняет высоту окна. Экран сцены следует за `100dvh`, но длины закреплений при этом
  не пересчитываются (иначе страница прыгала бы). Фон на весь экран делайте с запасом по высоте
  (`min-h-[100lvh]` у абсолютного слоя), чтобы снизу не появлялась полоса.
- `env.h` на телефоне не обновляется от панели адреса: не привязывайте к нему точную вёрстку, берите проценты.

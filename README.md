# Афиша культуры Башкортостана

Приватный репозиторий команды для подготовки к хакатону «Кибер 102» и разработки единой достоверной афиши культурных событий республики.

## Продукт

Планируемые интерфейсы и контуры:

- веб-сервис с поиском, чипами условий, сравнением сеансов (`Occurrence`) и конструктором плана дня;
- Telegram-бот с нативными in-bubble HTML-виджетами **Bot API 10.4** (`sendWidget` + `editMessageWidgetData` + `WidgetQuery`, релиз 09.11.2026) и переходом к полной карте;
- открытый REST API и встраиваемый партнёрский веб-виджет;
- двухсистемный ИИ-куратор: **System 1 (`Jev`, TypeSafe AI)** для мгновенных типизированных решений (`Noul`, `Choice`, `Score`) + **System 2 (`LLM Structured Output`)** для разбора свободных запросов и объяснения подборки поверх детерминированного ядра БД.

Ключевое ограничение: мероприятия должны быть проверяемыми. ИИ не является источником событий, не вычисляет жёсткие фильтры вместо backend'а и работает только с реальными данными из единого каталога (с обязательным fallback при отключении ИИ).

## Текущий этап

Подготовка к хакатону: завершены продуктовые, UX-, поисковые и ИБ-исследования, подготовлены контрактные схемы и 384 синтетических сценария в `evals/`, зафиксированы архитектурные решения по контуру `Jev` (`D-013`) и виджетам Telegram Bot API 10.4 (`D-014`).

## Базовые принципы

1. Один источник данных для сайта, Telegram-виджетов, API и внешнего партнёрского виджета.
2. У каждого события и сеанса (`Occurrence`) есть первоисточник, время последней проверки и явный статус (`unknown` ≠ `0` / `бесплатно`).
3. Жёсткие ограничения проверяет детерминированный backend; `Jev` и `LLM` работают строго в границах типизированных контрактов и серверных allowlist'ов.
4. Сначала сквозной MVP, затем экспериментальные функции.
5. Секреты, токены и персональные данные не хранятся в репозитории.
6. Каждое демонстрируемое событие можно проверить по первоисточнику.

## До начала разработки

- Добавить всех участников команды в collaborators с минимально необходимыми правами.
- Включить защиту `main`: запрет прямых push и force-push, обязательный PR и минимум одно ревью.
- Назначить владельцев направлений и заполнить таблицу в `docs/DECISIONS.md`.
- Согласовать состав MVP и критерии готовности демо.

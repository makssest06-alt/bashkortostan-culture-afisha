# Афиша культуры Башкортостана

Командный репозиторий хакатона «Кибер 102», задача 1 «Афиша культуры Башкортостана». Официальное ТЗ: [`docs/TZ.pdf`](docs/TZ.pdf).

Делаем информационный сервис о культурных событиях республики: концерты, спектакли, выставки, фестивали, кино, экскурсии. Один каталог и один REST API обслуживают Telegram-бота, сайт, встраиваемый виджет и ИИ-агента. Министерство может забрать данные через открытый API и встроить виджет к себе, не меняя свои системы.

> Это **неофициальный** сервис команды хакатона. Он не является сервисом Министерства культуры Республики Башкортостан, и интерфейс должен говорить об этом явно (ТЗ, п. 13, «красные линии»).

## Уровень решения

**Выбран уровень 3 «Агент» (85 баллов).**

- Уровни кумулятивные: уровень 3 = бот (ур. 1) + сайт, API, виджет, админка, дедупликация (ур. 2) + ИИ-агент в боте и на сайте.
- Уровень 4 добавляет сбор из внешних источников, планировщик «Выходной день», 60 контрольных запросов с отчётом. Для 48 часов это большой риск.
- Оценка = баллы уровня × коэффициент качества. Аккуратный уровень 2 может обойти уровень 3 с проваленными метриками (п. 5). Поэтому запасной план — сдать уровень 2 и включить агента, только если его метрики проходят пороги п. 9.2.

После решения команды уровень нужно записать сюда и в описание решения.

## Запуск

### Целевой запуск: одна команда

По ТЗ (п. 10) сервис поднимается так, на чистой машине, не дольше 10 минут:

```bash
cp .env.example .env   # заполнить токен бота и ключ модели
docker compose up
```

**Сейчас этой команды нет.** `docker-compose.yml` и `.env.example` появятся вместе с бэкендом. В compose войдут база с миграциями и тестовыми данными, API, бот и сайт.

### Сайт сейчас

Работает после влития PR #17 (или в ветке `feat/web-site`):

```bash
cd web && npm ci && npm run dev
# открыть http://localhost:3210
```

### Проверка контрактов

```bash
npx --yes @redocly/cli@1 lint contracts/api.openapi.yaml
```

## Контракт v1: один для фронта, бэка и бота

| Файл | Что описывает |
|---|---|
| [`contracts/event.schema.json`](contracts/event.schema.json) | Событие строго по п. 8.1 и необязательные расширения (JSON Schema 2020-12) |
| [`docs/EVENT_SCHEMA.md`](docs/EVENT_SCHEMA.md) | Правила полей: цена, статусы, дедупликация, формат импорта |
| [`contracts/api.openapi.yaml`](contracts/api.openapi.yaml) | REST API `/api/v1`: публичные методы и админка, ошибки, кеширование (OpenAPI 3.1) |
| [`contracts/agent_tools.json`](contracts/agent_tools.json), [`docs/AGENT_TOOLS.md`](docs/AGENT_TOOLS.md) | Шесть инструментов агента п. 7.2, лимит пяти шагов, подтверждение изменений |

Правило: сначала меняется контракт и согласуется с затронутыми сторонами, потом код. Поле, которого нет в контракте, никто не отдаёт и ни на что не опирается.

## Модель и стоимость диалога

**Не заполнено.** По ТЗ (п. 11, 9.2) здесь нужно указать модель, среднюю стоимость диалога и способ расчёта. Порог для уровня 3 — не больше 5 ₽ за диалог. Заполняет владелец агента.

## Данные и персональные данные

- Выдуманных мероприятий нет. Демо-события синтетические и помечены `synthetic: true`.
- Подписка хранит только непрозрачный идентификатор пользователя `user_ref` и фильтры: без телефонов и адресов. Отписка удаляет запись.
- Срок хранения подписок: **согласовать** с командой и заказчиком (Прил. В). Предложение: до отписки, но не дольше 6 месяцев без активности.
- Имя и контакт из формы обратной связи нужны только для ответа организатору и не пишутся в логи. Срок хранения тоже нужно согласовать.

## Известные ограничения

- Подготовленного набора событий от заказчика пока нет, состав и срок передачи не известны (Прил. В).
- Башкирские тексты сайта не проверены носителем языка.
- Метрики п. 9 не измерялись: нет каталога, бэка и скрипта прогона.

## Базовые принципы

1. Один каталог и один API для сайта, бота, виджета и агента.
2. У каждого события есть источник, время проверки и статус. Неизвестная цена (`null`) — это не «бесплатно», неизвестный возраст — не «0+».
3. Отменённое событие не попадает в выдачу, но открывается по прямой ссылке с пометкой.
4. Жёсткие фильтры (дата, город, цена, возраст, статус) проверяет детерминированный код. Агент берёт факты только из результатов инструментов.
5. При отключённой модели поиск и карточки работают.
6. Секреты, токены и персональные данные не попадают в репозиторий и логи.
